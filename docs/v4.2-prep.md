# v4.2 prep: where the code is today

Groundwork for the [v4.2 checklist (PR #39)](https://github.com/AnimatedGTVR/Abora-OS/pull/39): a map of the
current code, measured on `edge` at `5a83205` (v4.1 Horizon). It records facts only. The decisions (ANIX,
TinyPM, ASA) are still open.

## Baseline

- `python3 scripts/check-scripts.py` (what `make check` runs) passes all **321 checks** in about 26 seconds
  in WSL Ubuntu 24.04 with Nix. Any refactor should keep this at 321 passing, or explain why a check moved.
- Run it from a Linux clone, not from a Windows checkout. `scripts/*` holds 47 symlinks into the subfolders,
  and Git on Windows checks them out as one-line text files, so the checks fail there.

in tools as well. The checklist says to avoid adding another language unless there is a real reason. On
current numbers, C# (two small tools) is the clearest candidate to fold into Python or Vanta.

## Duplication found

1. **Command wiring is written twice.** `nix/profiles/live.nix` and `nix/modules/installed-base.nix` each
   define about 31 command wrappers, and 27 of those commands are the same in both. One shared list (a Nix
   function or a `commands.nix` both import) would remove about half of that.
2. **Two doctors.** `abora doctor` (`scripts/support/abora-doctor.py`, 319 lines) checks installed files,
   Flathub, the update channel and the desktop, and then calls `anix doctor`.
   - `anix doctor` (in `anix.sh`) checks nix and nixos-rebuild, the config directory, flake evaluation, Git
     state, ANIX config preflight, the desktop and the generation profile, and has a `--fix` mode.
   - **Overlap:** both check the desktop. Only ANIX can repair anything.
   - **Fit with the checklist:** section 5 (`abora doctor` as a major feature) is a merge of these two plus
     the new checks (bootloader, GPU, network and DNS, disk, services).
3. **Two rollbacks.** `abora rollback` goes to `abora-update rollback` (version/channel rollback), while
   `anix rollback` rolls back NixOS generations. Users see two commands with the same name doing different
   things. This is the main input to ASA/ABT (section 6).
4. **The tests enforce copy-paste.** Two checks are "redaction is identical in `abora-check-full.py` and
   `abora-support-report.py`" and "the UI block is identical in every support tool that has one". Shared
   code is being kept in sync by hand. Moving it into a shared module (section 4, Unified Core) lets those
   tests become plain unit tests of that module.
5. **Two UI libraries for shell.** `scripts/core/abora-ui.sh` is sourced by shell tools, but `anix.sh`
   carries its own fallback copy of the UI functions for running outside Abora OS.

## `abora` and `anix` side by side

`abora` (551 lines) is mostly a dispatcher: almost every subcommand `exec`s a separate tool (`abora-config`,
`abora-desktop`, `abora-update`, `abora-doctor` and so on). It has about 30 subcommands.

`anix` (3,384 lines) is one large program with its own logic for about 35 subcommands:
- **Config:** `init`, `edit`, `set`, `enable`/`disable`, `package`, `service`.
- **Rebuilds and generations:** `apply`, `test`, `boot`, `switch`, `diff`, `generations`, `rollback`.
- **Snapshots:** `save`, `gc`.
- **Plans:** `validate-plan`, `apply-plan`, `diff-plan`.
- **Languages:** `language`, `run`.
- **Other:** `doctor`, `tinypm`, a GUI and a learn/cheatsheet.

Commands both have: `learn`, `doctor`, `rollback` (different meaning), and config/desktop changes (`abora
config` and `abora desktop` against `anix set desktop`).

**Fit with the checklist:** under either section 2 option (ANIX as the engine behind `abora`, or absorbed
into it), the work is the same first step. Split `anix.sh` into a library of operations (config edit,
rebuild, generations, snapshots) and a thin CLI, so `abora` can call the operations directly instead of
going through a second CLI.

## TinyPM footprint

305 mentions in 48 files:
- **Code:** `anix.sh` (36), the installer (12), `installed-base.nix` (16), `nix/modules/anix.nix`,

- **Packaging and publishing:** `scripts/release/package-tinypm.py` and `build-tinypm-image.py`, the

**Fit with the checklist:** archiving it (section 3, option B) touches all of the above. Keeping it means
writing down its one purpose first.

## Atlas

Atlas appears **nowhere in this repo**. It lives only on the website (`Abora-OS-website`): `app/atlas/`, the
navigation, footer, docs sidebar, the Cloud and Forums pages, the home page use-cases section, and a blog
post. Section 1 of the checklist is a website change.

## Safety and recovery that already exist

- **Updater:** `abora-update` (shell) with its decision logic in Vanta (`tools/abora-update`). It already has
  a downgrade guard, an atomic `flake.nix` write with backup, free-space hard stops, an incomplete-checkout
  check and clear failure messages, all covered by tests.
- **ANIX:** generations, rollback, `save` snapshots (Git-backed config repo), `gc`, and plan files
  (`validate-plan`, `diff-plan`, `apply-plan`) built by the C# plan tool. These are the closest thing to
  ASA's PLAN, VALIDATE and APPLY steps today.
- **Recovery:** `abora-recovery.py` (actions plus network diagnostics, survives failing actions).

**Fit with the checklist:** ABT can start from the ANIX plan flow (it already plans, validates and applies)
and the updater's guards, rather than from scratch. Those are the two places that already do
"check, then change, then fall back".

## Suggested order (proposal, not decided)

1. **Shared module first (section 4).** Pull the duplicated UI block and redaction into one Python module,
   and `abora-ui.sh` into the one shell library `anix.sh` also uses. This is low-risk, the existing tests
   cover it, and later work builds on it.
2. **One command list for Nix (section 7).** Generate the `live.nix` and `installed-base.nix` wrappers from
   one list.
3. **Doctor merge (section 5).** One `abora doctor` with the ANIX checks inside it, then the new checks, a
   `--json` output and `abora doctor repair`.
4. **Decide ANIX and TinyPM (sections 2 and 3)**, then split `anix.sh` into operations and a CLI.
5. **ASA/ABT (section 6)** on top of the ANIX plan flow and the updater guards.
6. **Atlas removal (section 1)** on the website, at any time.

Vanta changes (you are updating Vanta now) mainly affect `tools/abora-update`, `nix/pkgs/vanta.nix`, the
Labs toolchain (`configs/languages.toml`, `automation/abora_labs/toolchain.py`) and the Vanta checks in
`scripts/release/check_scripts/setup.py`.
